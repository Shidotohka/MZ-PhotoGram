# 摄影测量工作台

课程项目：一个能跑、能对答案、能讲清楚的桌面摄影测量程序（C# + WPF）。

从影像出发，走完：

```
影像 → 内定向 → 像平面坐标 → 后方交会 → 外方位 ─┐
                                                 ├→ 前方交会 → 地面坐标
            → 相对定向 → 绝对定向 ───────────────┘
```

不做自动匹配、区域网平差、密集匹配、DEM / 正射影像。

---

## 快速开始

```powershell
# 先编算法 DLL
cmake -S native -B native/build -G "Visual Studio 17 2022" -A x64
cmake --build native/build --config Release

# 算法自检（内定向 + 后方交会）
native\build\bin\Release\pgm_test.exe Data/sim
native\build\bin\Release\pgm_resection_test.exe

# 再编界面
dotnet build src/App/App.csproj -c Debug
dotnet run --project src/App/App.csproj
```

需要 .NET SDK 10、MSVC（VS2022）与 CMake。托管侧不依赖任何 NuGet 包，可离线还原。

## 几条贯穿全项目的约定

1. **坐标分四类，各有类型**：屏幕 / 像素 / 像平面 / 地面。绝不共用一个 `Point`。
2. **C++ 只做纯计算，脏数据在 C# 洗干净**。平差、迭代、投影在 `native/`，它假设拿到的已经是干净的右手系；读文件、认格式、判手性、换轴、统一单位在 `Core`。判归属只问一句：这段代码需不需要知道数据从哪来。见[界面设计规范 §8.1](Docs/界面设计规范.md)。
3. **同一件事只有一份实现**。像素↔像平面换算就 `CoordinateConverter` 一份，界面读数与算法输入共用同一函数。
4. **每个算法都要能被手算验证**。算完能对上，才算做完。
5. **数据先合成、后真实**。合成数据有真值，能精确判对错；真实数据用来证明它能用。
6. **进度只写在路线图里**，别的地方不重复，避免一处更新一处过期。
